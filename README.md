# UML Editor Demo
本次專案為個人專案，目標是完成一個最基本的 Workflow Design 編輯器 。請大家務必詳閱附件的規格需求文件，並依照以下規範進行開發：
請用 Java Swing 來實作 UML Editor。

系統功能需完整對應 [附件](./Oops%20UML%20Editor%20-%20requirements.pdf) Spec 中定義的 Use Cases（包含建立、連結、選取、群組、移動、縮放與自定義標籤等） 。

專案中繪製的圖案與箭頭形狀，請盡量符合 Spec 示意圖中的大致樣貌

本專案開放使用 AI 工具輔助開發，但同學必須對專案的實作細節有充分的了解，助教將於 Demo 現場進行問答驗證。 

期中 Demo 階段「不會」針對程式碼的架構好壞進行評分，但架構評分將會在期末進行。也就是說，你現在寫得越符合 OO，期末就越輕鬆。

期末分數評斷標準如下：

1. 功能完整度（如果期中功能有缺漏的地方請務必補齊）- 20%
2. 物件導向的程度 - 50%
3. 程式碼的可讀性 - 15%
4. 程式碼與設計對應程度（你所畫的 Class Diagram 是否完全對應到你的程式或專案架構）- 15%
5. 專案熟悉程度（和期中專案一樣，你是否了解自己的程式碼實作細節與設計）

【重要提醒】助教將於現場隨機詢問 3 題與你專案相關的問題。若無法回答，將依比例倒扣第 2, 3, 4 項的分數，也就是說如果都回答不出來最高只會有 20 分。所以請務必熟悉自己的專案，以免影響最終成績。

> 提醒：用一個 swtich 扣 10 分（物件導向程度分）。
